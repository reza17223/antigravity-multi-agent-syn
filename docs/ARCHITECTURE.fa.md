# معماری فنی: هماهنگی چند-ایجنتی و چند-ماشینی (`agsync`)

[فارسی](ARCHITECTURE.fa.md) | [English](ARCHITECTURE.md)

## ۱. چرا ایجنت‌های کدنویسی محلی به لایه هماهنگی بیرونی نیاز دارند؟

ابزارها و ایجنت‌های کدنویسی هوش مصنوعی (Antigravity، Claude Code، Cursor، Windsurf، Codex، Gemini CLI) روی سیستم هر برنامه‌نویس به‌صورت محلی اجرا می‌شوند:
1. **وضعیت ایزوله روی هر سیستم:** تاریخچه گفتگوها، کش‌های محلی، تنظیمات MCP و مجوزهای Workspace روی دیسک همان دستگاه نگه‌داری می‌شوند (مثلاً Antigravity داده‌هایش را در `~/.gemini/antigravity/` و `~/.gemini/config/mcp_config.json` نگه می‌دارد).
2. **نبود شبکه داخلی بین ایجنت‌ها یا قفل توزیع‌شده:** یک نصب محلی نمی‌تواند به‌صورت ذاتی ایجنت سیستم کناری را پیدا کند، تسک‌ها را اتمیک تقسیم کند یا قبل از ویرایش روی فایل‌ها قفل بین‌ماشینی بگذارد.
3. **محدودیت ابزارهای تک‌میزبان:** ابزارهای هماهنگی محلی (مثل Swarmهای تک‌سیستمی) فقط مکالمات روی یک سیستم واحد را مدیریت می‌کنند و میان چند کامپیوتر یا چند IDE مختلف کار نمی‌کنند.

## ۲. پاسخ صریح: آیا در همکاری کنار هم هم به Git نیاز داریم؟

**بله — حتی روی دو سیستم کنار هم، Git برای کدنویسی موازی و امن ضروری است، اما Git به‌تنهایی برای هماهنگی لحظه‌ای کافی نیست.**

- **چرا Git ضروری است:**
  1. **جداسازی کش‌ها و محیط اجرا:** ایجنت‌ها پکیج نصب می‌کنند (`node_modules/`، `.venv/`)، کش بیلد می‌سازند (`__pycache__/`، `dist/`) و تست اجرا می‌کنند. کلون‌های مجزا (یا `git worktree` محلی) جلوی تداخل فایل‌ها و قفل‌های بیلد را می‌گیرند.
  2. **بازگشت امن (Rollback):** با `git diff` و `git restore` می‌توان تغییرات خراب یک ایجنت را بدون آسیب به کد همکار برگرداند.
  3. **ادغام قطعی (3-Way Merge):** تغییرات غیرهم‌پوشان تمیز ادغام می‌شوند و تداخل‌های واقعی خط‌به‌خط مشخص می‌گردند.
- **چرا Git به‌تنهایی کافی نیست:** Git فقط **بعد از Commit و Push** وضعیت را منتقل می‌کند؛ در زمان ویرایش‌های باز (۱۰ تا ۲۰ دقیقه‌ای)، Git دیدی درباره مالکیت تسک‌ها، فایل‌های در حال ویرایش یا تغییرات لحظه‌ای قراردادهای API نمی‌دهد.
- **بدون نیاز به اینترنت:** می‌توان یک مخزن Bare محلی روی شبکه LAN (با SSH یا اشتراک محلی) راه‌اندازی کرد.

## ۳. ماتریس مقایسه ۴ روش

| معیار | (الف) فقط Git و برنچ | (ب) پوشه اشتراکی (SMB / NFS) | (ج) همگام‌ساز فایل (Syncthing / Mutagen) | (د) **روش پیشنهادی هیبرید: Git ایزوله + هاب `agsync`** |
|---|---|---|---|---|
| **ایزوله‌سازی فایل‌های کاری** | بالا (دیسک محلی) | **ندارد** (پوشه مشترک) | پایین (تغییر مداوم از بیرون) | **بالا** (کلون/worktree و برنچ جداگانه) |
| **ریسک بازنویسی خاموش** | ریسک کار تکراری بالا | **بحرانی** (مسابقه `read->write`) | **بالا** (فایل‌های `.sync-conflict-*`) | **حذف‌شده** (قفل انحصاری پیش از ویرایش) |
| **ریسک خرابی `.git`** | ندارد | **بالا** (مسابقه `.git/index.lock`) | **بحرانی** (خرابی refs/HEAD) | **ندارد** (`.git/` کاملاً محلی می‌ماند) |
| **تداخل کش‌های بیلد** | ندارد | **بحرانی** (`EBUSY` / باینری‌های ناسازگار) | **بالا** بدون فیلتر دقیق | **ندارد** |
| **هماهنگی لحظه‌ای ایجنت‌ها** | **ندارد** | ندارد | ندارد | **کامل** (MCP + HTTP + CLI + Hooks) |
| **پشتیبانی از چند IDE / ایجنت** | دستی | خراب | خراب | **کامل** (هر ایجنت سازگار با MCP/HTTP/CLI) |

## ۴. معماری لایه کنترل `agsync` و طراحی ماژولار (فاز ۱)

```text
+----------------------------------------+        LAN / Local HTTP        +----------------------------------------+
|          Machine A / Agent A           |  <-------------------------->  |          Machine B / Agent B           |
|  (Antigravity / Claude / Cursor / CLI) |                                |  (Antigravity / Claude / Cursor / CLI) |
|   |-- AGENTS.md + .agents/skills/      |                                |   |-- AGENTS.md + .agents/skills/      |
|   |-- PreToolUse hook_guard.py         |                                |   |-- PreToolUse hook_guard.py         |
|   '-- MCP (/mcp or mcp_bridge.py) -----+--+                          +--+--- MCP (/mcp or mcp_bridge.py)       |
|                                        |  |                          |  |                                        |
|  agsync.server (0.0.0.0:8765 + Token)<-+--+--------------------------+  |  Local Git Clone (branch: agent-b/*)   |
|   |-- db.py (SQLite WAL + user_version)|                                |   '-- git pre-commit guard (--staged)  |
|   |-- core/{locks,events,git_ops}.py   |                                +----------------------------------------+
|   |-- adapters/{network,ide}.py        |
|   '-- ~/.agsync/state.db (+ .pid lock) |
+----------------------------------------+
```

### تضمین‌های کلیدی و سخت‌سازی‌ها
1. **سریال‌سازی اتمیک و تفکیک خواندن/نوشتن (`db.py`، `core/locks.py`، `core/events.py`):**
   - عملیات نوشتن با `BEGIN IMMEDIATE` و `RLock` سریال‌سازی می‌شوند، خطای `COMMIT` ایمن rollback می‌شود و اسکیما با `PRAGMA user_version` مدیریت می‌گردد.
   - مسیرهای خواندنی (`/health`، `/leases`، `/leases/check`، `/snapshot`، `/state/export`) در تراکنش خواندنی (`read_tx()`) با شرط SQL `expires_at > now` اجرا می‌شوند.
   - `import_state` پیش از `replace=True` بکاپ آنلاین `.bak` می‌سازد و `MAX(existing, imported)` را برای `fencing_seq` و `task_seq` حفظ می‌کند.
2. **نرمال‌سازی سلسله‌مراتبی و امنیت Junction (`protocol.py`، `hook_guard.py`):**
   - مسیرها یکسان‌سازی می‌شوند (`\` به `/`)، traversal (`..`) و مسیر درایو رد می‌شوند و `hook_guard.py` با مسیر منطقی `abspath`/`normpath` از فرار Windows Junction جلوگیری می‌کند.
   - فایل‌های حساس (`.agsync/**`، `.agsync-agent`، `.agents/hooks.json`) پیش از درخواست به سرور مسدود می‌شوند.
3. **سخت‌سازی HTTP، CSRF، پروکسی و ویندوز (`server.py`، `adapters/network.py`، `adapters/ide.py`):**
   - اجبار `Content-Type: application/json` (`415`)، کنترل `Host`/`Origin` (`403`)، خواندنی‌بودن `GET /messages`، تایم‌اوت ۳۰ ثانیه و پاسخ `500` JSON برای استثناها.
   - قفل انحصاری سوکت `SO_EXCLUSIVEADDRUSE` + فایل قفل `<db>.pid`، دور زدن پروکسی روی LAN (`ProxyHandler({})`)، پشتیبانی BOM/UTF-16، تشخیص `--git-common-dir` / `--git-path hooks` در worktree و ادغام اتمیک JSON با `.bak`.
4. **دفاع چندلایه (Defense-in-Depth):**
   - **لایه ۱ (رفتاری):** `AGENTS.md` + `skills/`
   - **لایه ۲ (هوک ابزار زمان اجرا):** `PreToolUse` (`hook_guard.py`)
   - **لایه ۳ (هوک کامیت گیت):** `pre-commit` (`agsync guard --staged`)
   - **لایه ۴ (ایزوله‌سازی برنچ گیت):** کلون و برنچ مستقل برای هر ایجنت.
