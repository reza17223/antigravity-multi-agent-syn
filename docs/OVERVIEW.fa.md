# معرفی کامل و راهنمای ساده `agsync`: این ابزار دقیقاً چیست و چه دردی را دوا می‌کند؟

اگر بخواهیم در یک جمله بگوییم:
**`agsync` مثل یک «واکی‌تاکی + تابلوی اعلانات + قفل هوشمند» بین دو یا چند ایجنت Antigravity است که روی سیستم‌های جداگانه روی یک پروژه کار می‌کنند.**

---

## ۱. اصلاً مشکل چی بود که این را ساختیم؟

فرض کنید شما و همکارتان کنار هم نشسته‌اید و هر دو یک پروژه (مثلاً یک سایت یا اپلیکیشن) را داخل **Antigravity** باز کرده‌اید:
- **مشکل ۱ (ناآگاهی ایجنت‌ها از هم):** ایجنت Antigravity سیستم شما اصلاً نمی‌داند ایجنت همکارتان الان دارد چه فایلی را تغییر می‌دهد یا چه تصمیمی گرفته است.
- **مشکل ۲ (تداخل و بازنویسی کد):** ممکن است ایجنت شما فایل `auth.py` را تغییر دهد و هم‌زمان ایجنت همکارتان هم همان فایل را تغییر دهد؛ موقع Merge یا ذخیره کردن، کدها به هم می‌ریزند و کار هر دو خراب می‌شود.
- **مشکل ۳ (محدودیت Antigravity):** خود نرم‌افزار Antigravity فقط به صورت محلی روی یک سیستم کار می‌کند و قابلیت داخلی برای وصل شدن به Antigravity سیستم کناری ندارد.

---

## ۲. راه‌حل `agsync` دقیقاً چیکار می‌کند؟

به جای اینکه فقط روی شانس حساب کنید، این سیستم کار را به **۳ لایه ساده** تقسیم می‌کند:

1. **کد هر کس امن بماند (`Git`):**
   هر سیستم کد خودش را روی یک برنچ (Branch) جداگانه دارد (مثلاً `feature/soheil` و `feature/hamkar`). هیچ‌کس مستقیم روی فایل‌های خام سیستم دیگری نمی‌نویسد که فایل‌ها یا کش بیلد خراب شوند.
2. **هماهنگی زنده بین ایجنت‌ها (`agsync Hub` + `MCP`):**
   یک سرور سبک روی یکی از سیستم‌ها (یا سرور مشترک) اجرا می‌شود و از طریق پروتکل **MCP** چند ابزار جدید به منوی مغز Antigravity اضافه می‌کند. حالا ایجنت شما می‌تواند به ایجنت همکارتان **پیام بفرستد**، **تسک‌ها را بین هم تقسیم کند**، و **قبل از ویرایش هر فایل روی آن قفل بگذارد**.
3. **جلوگیری خودکار از اشتباه (`Hooks`):**
   حتی اگر ایجنتی فراموش کند بپرسد، هوک‌های نصب‌شده داخل پروژه (`PreToolUse` و Git `pre-commit`) **اجازه نمی‌دهند** فایلی که الان دست همکارتان قفل است را ویرایش یا کامیت کند!

---

## ۳. پس قراره دقیقاً چیکار کنیم؟ (از صفر تا استفاده واقعی)

شما دو حالت دارید: **تنظیمات بار اول (فقط یک‌بار)** و **کار روزانه (در ۱۰ ثانیه)**.

### مرحله اول: تنظیمات بار اول (روی هر سیستم یک‌بار انجام می‌شود)

کافیست روی فایل **`Start_Sync_Panel.bat`** دبل‌کلیک کنید تا پنل کنترل (شبیه XAMPP) باز شود:

#### روی سیستم اول (میزبان / Host):
1. بالای پنل نقش را روی **`HOST (Hub)`** بگذارید.
2. یک نام در **`Agent ID`** بنویسید (مثلاً `soheil` یا `machine-a`).
3. دکمه **`Open Firewall (Admin)`** را بزنید تا ویندوز اجازه عبور اتصال از پورت‌های `8765` و `8766` را بدهد.
4. دکمه **`Start Hub Server`** را بزنید (چراغ سبز می‌شود: `HOST RUNNING :8765`).
5. پایین پنل، پوشه پروژه اصلی‌تان را انتخاب کنید (**`Browse...`**) و دو دکمه زیر را بزنید:
   - **`Connect Antigravity MCP`** ← ابزارهای هماهنگی را به Antigravity شما اضافه می‌کند.
   - **`Install Repo Hooks & Templates`** ← قوانین و قفل خودکار را روی پوشه پروژه می‌گذارد.

#### روی سیستم دوم (همکار) و سیستم‌های سوم، چهارم...:
*(کافیست همین پوشه `antigravity_multi_agent_sync` را روی سیستمشان داشته باشند)*
1. فایل **`Start_Sync_Panel.bat`** را باز کنید.
2. نقش را روی **`PEER (Client)`** بگذارید.
3. یک **`Agent ID` یکتا** بدهید (مثلاً `machine-b`، نفر سوم `machine-c`).
4. آی‌پی سیستم Host را در **`Host LAN IP`** وارد کنید (یا **`Discover LAN Hub`** را بزنید تا خودش پیدا کند).
5. دکمه **`Test Connection (Ping + /health)`** را بزنید:
   - اگر سبز شد (`CONNECTED`) عالیه!
   - اگر خطای `PING FAILED` داد یعنی VPN اجازه عبور شبکه محلی را نداده؛ اگر `HTTP FAILED` داد یعنی سرور Host روشن نیست یا فایروال بسته است.
6. پایین پنل، پوشه کلونِ پروژه اصلی روی همان سیستم را انتخاب کرده و دو دکمه **`Connect Antigravity MCP`** و **`Install Repo Hooks & Templates`** را بزنید.

> **نکته:** بعد از این تنظیم، یک‌بار Antigravity را ری‌استارت/ریلود کنید تا ابزارهای MCP جدید را بشناسد.

---

### مرحله دوم: کار روزانه (وقتی می‌خواهید با هم کد بزنید)

1. هر روز سیستم میزبان فقط **`Start_Sync_Panel.bat`** را باز می‌کند و **`Start Hub Server`** را می‌زند.
2. هر کس پروژه اصلی خودش را در Antigravity باز می‌کند.
3. از داخل چت Antigravity می‌توانید از اسلش‌کامندها استفاده کنید یا مستقیم به ایجنت بگویید:
   - **`/sync-start`** ← ایجنت خودش را آنلاین ثبت می‌کند، پیام‌های همکار را می‌خواند و تسک‌ها را چک می‌کند.
   - هنگام کد زدن، ایجنت **خودکار** قبل از ویرایش هر فایل روی آن Lease (قفل) می‌گیرد و بعد از اتمام آزادش می‌کند.
   - اگر هم‌زمان هر دو نفر بخواهند یک فایل را دست بزنند، دومی خطا می‌گیرد و تداخل پیش نمی‌آید!
   - **`/sync-handoff`** ← وقتی کارتان تمام شد یا به برنچ وصل شدید، وضعیت را برای همکار ارسال می‌کند.
4. با زدن **`Open Web Dashboard`** در پنل (یا آدرس `http://<HOST_IP>:8765/dashboard` در مرورگر)، می‌توانید زنده ببینید چه کسانی آنلاین‌اند و هر فایل دست کیست!

---

### اگر سیستم Host خواست خاموش شود چه؟ (سوئیچ به Peer)
1. سیستم دوم در پنل نقش خودش را از `PEER` به **`HOST`** تغییر می‌دهد و **`Start Hub Server`** را می‌زند.
2. دکمه **`Pull State from Old Host...`** را می‌زند و آدرس Host قبلی را وارد می‌کند تا تمام قفل‌ها، تسک‌ها و پیام‌ها منتقل شوند.

---

## ۴. راهنمای سریع فایل‌های پروژه

| فایل یا پوشه | کاربرد به زبان ساده |
|---|---|
| `Start_Sync_Panel.bat` | **مهم‌ترین فایل برای شما:** پنل گرافیکی یکپارچه شبیه XAMPP برای مدیریت همه‌چیز |
| `agsync/` | هسته اصلی سرور، کلاینت، قفل‌گذاری، MCP، کشف شبکه و داشبورد وب |
| `templates/` | فایل‌های آماده قوانین (`AGENTS.md`)، تنظیمات MCP و اسکیل‌های `/sync-*` برای پروژه شما |
| `docs/OVERVIEW.fa.md` | همین راهنمای معرفی کامل و کاربردی |
| `docs/SETUP_GUIDE.fa.md` | راهنمای کوتاه دستورات خط فرمان (CLI) |
| `docs/ARCHITECTURE.md` | تحلیل فنی معماری (چرا Git لازم است و مقایسه روش‌ها) |
| `tests/` و `scripts/smoke_check.py` | تست‌های خودکار برای اطمینان از درست کار کردن کل سیستم |
