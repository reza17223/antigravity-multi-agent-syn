# معرفی کامل و راهنمای ساده `agsync`: این ابزار دقیقاً چیست و چه دردی را دوا می‌کند؟

[فارسی](OVERVIEW.fa.md) | [README فارسی](../README.fa.md) | [English README](../README.md)

اگر بخواهیم در یک جمله بگوییم:
**`agsync` مثل یک «واکی‌تاکی + تابلوی اعلانات + قفل هوشمند» بین دو یا چند ایجنت هوش مصنوعی (Antigravity، Claude Code، Cursor، Windsurf، Codex و غیره) است که روی سیستم‌های جداگانه یا کلون‌های مجزا روی یک پروژه کار می‌کنند.**

---

## ۱. مشکل چی بود که این را ساختیم؟

فرض کنید شما و همکارتان کنار هم (یا از راه دور) روی یک پروژه کار می‌کنید و هر کدام از یک ایجنت (مثلاً شما Antigravity و همکارتان Claude Code یا Cursor یا یک Antigravity دیگر) استفاده می‌کنید:
- **مشکل ۱ (ناآگاهی ایجنت‌ها از هم):** ایجنت سیستم شما نمی‌داند ایجنت همکارتان الان دارد چه فایلی را تغییر می‌دهد یا چه تصمیمی گرفته است.
- **مشکل ۲ (تداخل و بازنویسی کد):** اگر هر دو هم‌زمان فایل `auth.py` را تغییر دهند، هنگام Merge یا ذخیره کردن، کدها به هم می‌ریزند.
- **مشکل ۳ (محدودیت ابزارهای کدنویسی):** IDEها و CLIهای هوش مصنوعی به‌صورت محلی روی یک سیستم اجرا می‌شوند و امکان هماهنگی زنده بین چند دستگاه یا چند ایجنت ناهمسان را ندارند.

---

## ۲. راه‌حل `agsync` دقیقاً چیکار می‌کند؟

کار را به **۳ لایه ساده و مطمئن** تقسیم می‌کند:

1. **کد هر کس امن بماند (`Git`):**
   هر ایجنت/سیستم کلون و برنچ جداگانه خودش را دارد (مثلاً `agent-a/api` و `agent-b/ui`). هیچ‌کس مستقیم روی فایل‌های خام سیستم دیگری نمی‌نویسد که کش بیلد (`node_modules`، `.venv`، `__pycache__`) یا `.git` خراب شود.
2. **هماهنگی زنده بین همه ایجنت‌ها (`agsync Hub` + `MCP` / `CLI`):**
   یک سرور سبک روی یکی از سیستم‌ها اجرا می‌شود و از طریق استاندارد **MCP** (یا CLI/HTTP) ابزارهای مشترک را در اختیار هر ایجنتی می‌گذارد: **پیام فرستادن**، **تقسیم اتمیک تسک‌ها**، **انتشار قراردادهای API** و **قفل‌گذاری قبل از ویرایش فایل**.
3. **جلوگیری خودکار از اشتباه (`Hooks`):**
   حتی اگر ایجنتی فراموش کند بپرسد، هوک‌های نصب‌شده (`PreToolUse` و Git `pre-commit`) **اجازه نمی‌دهند** فایلی که الان دست همکارتان قفل است (یا فایل‌های حساس `.agsync/**`) ویرایش یا کامیت شود.

## ۳. چطور در عمل استفاده کنیم؟

### حالت پنل گرافیکی (ویندوز): روی `Start_Sync_Panel.bat` دبل‌کلیک کنید

#### روی سیستم اول (میزبان / Host):
1. بالای پنل نقش را روی **`HOST (Hub)`** بگذارید و یک **`Agent ID`** بنویسید (مثلاً `machine-a`).
2. دکمه **`Generate Token`** را بزنید تا توکن امنیتی ساخته شود (اگر نزنید، موقع Start خودکار ساخته می‌شود).
3. دکمه **`Open Firewall (Admin)`** را بزنید تا ویندوز عبور از پورت‌های `8765` (TCP) و `8766` (UDP) را در پروفایل `Private` باز کند.
4. دکمه **`Start Hub Server`** را بزنید (`HOST RUNNING :8765`).
5. پایین پنل، پوشه پروژه اصلی را انتخاب کنید (**`Browse...`**) و بسته به ابزارتان:
   - برای Antigravity: دکمه **`Connect Antigravity MCP`** را بزنید.
   - برای کلاینت‌های دیگر (Claude Code، Cursor، Windsurf): بخش MCP را مطابق [راهنمای گام‌به‌گام](SETUP_GUIDE.fa.md) تنظیم کنید.
   - دکمه **`Install Repo Hooks & Templates`** را بزنید تا قوانین `AGENTS.md`، اسکیل‌ها و هوک‌های محافظ روی پروژه نصب شوند.

#### روی سیستم دوم (همکار) و سیستم‌های بعدی:
1. فایل **`Start_Sync_Panel.bat`** را باز کنید و نقش را روی **`PEER (Client)`** بگذارید.
2. یک **`Agent ID` یکتا** بدهید (مثلاً `machine-b` یا `claude-b`).
3. آی‌پی سیستم Host را در **`Host LAN IP`** وارد کنید (یا **`Discover LAN Hub`** را بزنید) و همان **Token** میزبان را وارد کنید.
4. دکمه **`Test Connection (TCP + /health)`** را بزنید:
   - اگر سبز شد (`CONNECTED`) عالی است.
   - اگر **`TCP FAILED`** داد، یعنی سرور Host خاموش است یا فایروال/پروکسی-VPN مسیر LAN را بسته است.
   - همچنین هر زمان می‌توانید دکمه **`Run Doctor`** را بزنید تا تنظیمات محیط، پورت، پروکسی، فایروال و هوک‌ها بررسی شوند.
5. پروژه روی سیستم دوم را انتخاب و MCP + هوک‌ها را نصب کنید.

---

### کار روزانه (بین هر دو یا چند ایجنت)

1. میزبان فقط **`Start_Sync_Panel.bat`** (یا `agsync serve`) را روشن می‌کند.
2. هر کس پروژه خودش را در ایجنت دلخواهش باز می‌کند و در شروع جلسه به ایجنت می‌گوید طبق قوانین `AGENTS.md` (یا `/sync-start`) ثبت‌نام کند، پیام‌ها را بخواند و تسکش را Claim کند.
3. قبل از ویرایش هر فایل، ایجنت **Lease** می‌گیرد؛ اگر فایل دست همکار قفل باشد، با خطای `409 lease_conflict` متوقف می‌شود.
4. با **`Open Web Dashboard`** (یا آدرس `http://<HOST_IP>:8765/dashboard`) می‌توانید زنده ببینید کدام ایجنت‌ها آنلاین‌اند و هر فایل دست کیست.

### اگر سیستم Host خواست خاموش شود چه؟ (سوئیچ به Peer)
1. سیستم دوم در پنل نقش را از `PEER` به **`HOST`** تغییر می‌دهد و **`Start Hub Server`** را می‌زند.
2. دکمه **`Pull State from Old Host...`** را می‌زند و آدرس Host قبلی را می‌دهد تا تمام قفل‌ها، تسک‌ها و پیام‌ها با حفظ شمارنده Fencing Token (و بکاپ خودکار `.bak`) منتقل شوند.
